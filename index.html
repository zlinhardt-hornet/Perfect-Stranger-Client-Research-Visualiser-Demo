JSON schema

Every field below is optional except company.name — omit a section on a new record and the board just skips that column.

{
  "company": { "name": "", "ticker": "", "status": "Prospect",
               "tagline": "", "researchDate": "" },
  "positioning": [ "fact... (Source: Label https://...)" ],
  "stateOfBrand": {
    "strengths": [ "..." ], "tensions": [ "..." ], "opportunity": ""
  },
  "audience": "",
  "marketingApproach": [ "..." ],
  "recentEfforts": [ "..." ],
  "opportunities": [ "..." ],
  "waysIn": [ "..." ],
  "leadership": [
    { "name": "", "title": "", "confidence": "HIGH|MEDIUM|LOW|UNVERIFIED",
      "source": "Label https://...", "LinkedIn": "https://...",
      "email": "person@company.com", "notes": "", "target": false }
  ],
  "decision": "",
  "nextSteps": [ "..." ]
}
  • Any fact string can end with (Source: Label https://...) — it renders as a clickable citation. Leave the URL off for a plain, non-linked source tag.
  • A leadership record is flagged as a 🎯 recommended entry point if target is true, or automatically if their notes mentions "best entry point".
  • Confidence just needs to contain high, medium, low, or unverified (any case).
  • The decision box color is picked up from the wording in decision — "pursue" → green, "pass" / "not a fit" → red, anything else → amber.
For IT / Data: how this connects to Airtable
  • The JSON above is the data contract — it's exactly what this page needs, and exactly what an Airtable base could hand back.
  • Production shape: one Airtable base, one table per prospect record, with a linked "Leadership" table (rows → the leadership[] array).
  • Airtable's REST API needs a server-side API key — never exposed in this static frontend. A thin serverless function (Vercel/Cloudflare Worker/Lambda) would call Airtable, reshape the response into this exact JSON, and hand it to the browser.
  • This page's renderer doesn't change either way — it already consumes this shape. Swapping the paste box for a fetch('/api/prospect/yeti') call is the only change needed to go live.
  • The "Sync from Airtable" button above simulates that call (fixed delay, same YETI record) so the interaction pattern is demonstrable today without the integration built yet.
